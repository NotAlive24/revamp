## Computer-System Operation

- A modern general-purpose computer system consists of a CPU and a number of devices connected through a common bus that provides access to a shared memory, each controller is in charge of a specific type of device (example: disk drives, audio devices etc...).
- The CPU and the device controller can execute concurrently, this makes them compete for memory cycles, a memory controller is provided to synchronize access to the memory and ensures orderly access to the shared memory.
- For the computer to start running, for instance, when it's powered up or rebooted, it needs an initial program to run, these are initial program, these are typically stored in Read-Only Memory (ROM or EEPROM), these programs mostly tends to be simpler, they are sometimes called as **bootstrap program**.
- The bootstrap program must know how to locate the Operating System's kernel and load them into the memory, then the Operating system starts executing the first process, such as 'init'(short for initialization, this is the very first process started by the operating system during the boot sequence) and waits for some event to occur.
- The occurrence of an event is usually signaled by an interrupt from either the hardware or the software, hardware triggers interrupts by signaling the CPU directly through a system bus, but for software it executes special operation called a **system call** aka **monitor call**.
- Modern systems are mostly interrupt driven, if there is no process to execute, no I/O devices to service, no users to respond, then the Operating system goes idle, waiting for something to happen, most of the events are triggered by interrupts or **traps**.
- Traps (or exception) is a software generated interrupt caused by either an error (like dividing with zero) or by some user program that an Operating System service be performed (user interrupting by some actions) for each type of interrupt signals a separate segment of of code in the Operating System determines what to do.
- When the CPU gets interrupted, it instantly pauses its task (saving its current state in memory so it doesn’t corrupt data) and checks a pre-defined index table (the fixed location, which is a hardcoded list of memory addresses). This table points directly to the starting address of the emergency code it needs to run (the Interrupt Service Routine, or the tech equivalent of a panic button). The CPU jumps to that address, handles the issue (like processing an urgent hardware signal), and then uses its saved notes to snap back to its original work.
> Note we will look at these deeper, no worries if you don't understand this, also an **interrupt vector** is a specific memory address that identifies and points to the starting location of an **Interrupt Service Routine (ISR)**
- There are various types of interrupt vectors:
	- The most commonly used type is: 
		- Table of pointers:
			A table (usually in low memory) that stores the addresses of various ISRs (Interrupt Service Routine).
		- Indexing:
			Each devices is assigned a unique number that acts as an index to this table, this can help the system to locate the routine quickly and correctly. (MS-DOS and UNIX used interrupts in this manner)
>Note: Older systems used fixed addresses to store the address of the interrupted instructions, while modern systems stores them in more flexible ways to ensure the CPU can return where it left off.

- When an interrupt that requires the modification of processor state, it should first save its current state and complete the process and load back the saved state and resume its other processes as if the interrupt never occurred.
- A systemcall is the method used to request a service from the OS, the method varies by processor, but it typically involves a `trap` (Software generated interrupt) that directs the CPU to a specific location in the interrupt vector, few others have their own dedicated methods like MIPS R2000 family.

## I/O Structure

- As discussed early, a general purpose computer consists of a CPU and multiple device controllers that are connected through a common bus.. Each device controller is in charge of a specific type of device, depending on the controller, there maybe more than an attached device, like the small computer-systems interface (SCSI) computer can have seven or more devices.
- These controllers carry some local buffer storage (buffer is temporary local storage, its small 128 to 4096 bytes), it varies on each devices, for example: the size of the buffer on a disk is the same or a multiple of the smallest address possible of a disk, which would be a **sector** it is usually 512 bytes.

### I/O Interrupts

- To start an I/O operation the CPU starts an appropriate register within the device controller, the device controller check s the content and determines what action to take and send it to the local buffer.
- Once this ends, it sends an interrupt to the CPU by saying that it completed the task.
- Let's say there is a user process requesting an I/O. Now there are 2 possible outcomes:
	1) When the I/O  is started, the user process will stay idle till the I/O is complete and then once the I/O is complete, the CPU shifts to the user process, this is called **Synchronous I/O**.
	2) In this case, the CPU returns to the user program without waiting for the I/O to complete and also runs the other system operations.
- To make the CPU wait for I/O completion there are 2 ways,
	1) Use a special `wait` instruction, this puts the CPU on idle state till an interrupt occurs.
	2) The second method uses loops for waiting, and waits for an interrupt to occur, once interrupt occurs it transfers control to other processes.

### DMA Structure

- When the CPU handle everything on its own, it should also handle slow devices like terminals, since the inputs are slow the CPU has to pause it's current process and runs an ISR to move the character to a buffer and resumes its task.
- If this were to be used, the CPU had to pause its processes for every character I/O leaving no time for the actual process.
- To solve these DMA was introduced it was able to transfer an entire block of data directly between its own buffer storage and main memory with no CPU intervention, it generates only one interrupt per block instead of one per byte.
- Let's say that a user program or the OS request a data transfer, The OS finds an empty buffer for input (or a full buffer for output) from a pool, this buffer is typically 128 to 4096 bytes, depending on the device type.
- A portion of the OS is called the 'device driver' sets the DMA controller registers with the appropriate source address, destination address, and transfer length, then the DMA controller is instructed to the start I/O operation.
- This is great cause when the DMA is performing the data transfer, the CPU is free to perform other tasks, like everything has a drawback, DMA can hog all the memory cycles and slow down the CPU by giving it less memory cycles.
- Once the transfer is complete DMA sends an interrupt to the CPU once the transfer is complete.

## Storage Structure

- Computer programs must be in the main memory aka RAM to be executed, this is the only memory the CPU can access directly, These are made of semi-conductors technology these are also called as Dynamic RAM or DRAM, these store words in an array, each word containing a memory address.
- We can use instructions like `load` or `store` to interact with it, `load` moves the instruction from main memory to CPU register, while the `store` moves the instructions from registers to main memory.
- Ideally, we want the main memory to store the programs permanently, but it is not possible due to 2 simple reasons:
	1) Main memory is too small to store all the needed programs and data permanently.
	2) Main memory is volatile memory, meaning it loses data when power if turned off.
- Hence, we use secondary storage device to store all the programs when the device is turned off, these storage device are magnetic disks that is able to store both program and data, most programs like (web browsers, compiler etc...) are stored in these disks, then when booting, opened these are loaded into the main memory.
- Not only magnetic disks but there are Solid State Drives (SSDs) which are way faster than magnetic disks as they store data in electrical form.
