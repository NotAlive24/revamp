## What is an Operating System (OS)?

An **Operating System** is a program that acts as an intermediary between the application and the hardware

Operating Systems are varied depending on the purpose of there use:
- In mainframe these are mostly to utilize the hardware
- On PCs (Personal Computers), these support complex games, and many more applications
- On handhelds, these are optimized to make the interface intractable

The Operating System (OS) provides the means for using Computer Components, such as the hardware, software and data. We can have to Point of View (POV), the user and the system

### User View:
- Mostly varies by OS and the interface being used
- For a single person OS, it is more focused on making it easy to use
- Some sit in-front of a terminal connected to a mainframe or minicomputer, these doesn't have an user friendly interface due to it's optimization to perform better at transferring resources
Like these there are many types of user views in Operating Systems

### System View:
- An OS is the most closest to the hardware
- We can view an OS as a resource allocator
- An OS has many things to handle: hardware (CPU time, memory space, file-storage space and so on), software (Every single application that the user runs). The OS should decide how to allocate the resources to a program or user by calculating how much resources is needed.
- It also has to handle the Input and programs run by the user
- In general, however, we have no completely adequate definition of an Operating System
- The fundamental goal of an OS is to execute user programs and make the users work easier
- There is way more things on the OS view, but all these combined single piece of software is what we call an Operating System
- Each Operating System have their own requirements on hardware
- The storage is calculated in Gigabytes (GB). 1 GB has 1024 MB and I assume this is known by the user
- The OS is the one program that keeps running at all the time (That part is usually called the **kernel**)

### System Goals:
- Defining the exact goal can be tricky.
- The primary goal of **some** Operating System can be convenience for the user.
- These exist because it is much easier to compute with them then without them.
- Overall primary goal can be said as efficient operation, but still this is mostly for large, shared and multi-user systems.
- UNIX started with keyboard and a printer as its interface, over time it evolved and now it has a Graphical User Interfaces (GUIs).

## Mainframe Systems

These are the first computers used to tackle many commercial(Like Banking) and scientific application(Like Weather Forecasting).
We are gonna look into simple **batch systems**, where the computers runs one and only one application, to **time-shared systems**, which allows user interactions.

### Batch Systems
- Early computers were enormous machines run from a console, common inputs were line printers, tape drives and punched cards, the user took a bunch of **punched cards** and grouped it as a program, (the program, data and control information was called as a **job**), the output took long time to compute (minutes, hours, or even days), the output consisted of the result as well as some dump of memory and register contents for debugging.
- The operators **batched** together jobs with similar needs and ran them as a group, hence the programmers leave their program to the operator to batch them together and run it, the output was sent to the appropriate programmer.
- The CPUs were electrical so they were able to read and execute the mechanical inputs quickly, the difference is speed was very large, as the CPU can complete it's calculation in nanoseconds with thousands of instructions per seconds and the fast card readers took around 1200 cards per minute (This is also called as **bottle neck**).
- With the invention of disk technology this was controlled as multiple jobs were stored in a disk and were ready to be used, with direct access to the disks the operating systems were able to perform **job scheduling**, to use resources to perform tasks efficiently.

### Multiprogrammed Systems
- The most important aspect of job scheduling is the ability to multiprogram.
- A single user in general can't keep either the CPU or the I/O devices busy at all the times (this mean a single use can't hog all the traffic and other users should be able to use the system resources), multiprogramming organizes the jobs such that there is room for other users.
- The idea is: The OS keeps several jobs in the memory simultaneously, since the number of jobs that can be stored is much smaller than the job pool, the OS picks and begins to one of the many jobs in the memory, when a job requires interaction, the **job waits**, when the job waits it switches to another job and when this job waits it switches to another and so on.
- Each job has a wait time-out set, so when it reaches the wait time it eventually terminates the job, freeing the memory and processing power.
- As long as there is a job, the CPU won't stay idle.
- Multiprogramming is the first instance in which the system decides for the user, that's why it is highly sophisticated.
- When there are a lot of jobs in the memory and more incoming and the memory has not enough room, then making that decision is called **job scheduling**.

### Time-Sharing Systems
- Time-Sharing also know as **Multitasking**, this was invented to overcome the limitation of multiprogramming which did not provide the user interaction with computer system.
- Time-Sharing is a logical extension of multiprogramming, the CPU executes all the jobs switching among each one very frequently, enabling the user to interact with the running program.
- An interactive (or hands-on) computer system provides direct communication between the user and the system, the user is able to give instruction directly using a keyboard or mouse, and the responds is typically within a second or so.
- Time-Sharing also enables multiple users to use one system by making the CPU switch the users rapidly from one user to another, giving the impression that the user is using a dedicated system of their own, even though it is being shared among multiple users.
- A program loaded into the memory and is being executed is commonly known as a **process**, the process typically finishes in a short amount of time unless an I/O is to be required.
- When an input is required, the process has to wait till the user enters an input, for example: 7 characters per second is faster for humans, but for computers that's incredibly slow, when the interactive input takes play the CPU rapidly switches to some other program of some other user.
- In both, Time-Sharing OS and Multiprogrammed OS it is difficult to manage memory and protect it, to obtain a reasonable response time, jobs gets swapped in and out of the main memory to the disk which serves as a backing store for the main memory.
- **Virtual memory** is a technique that allows the execution of a job that may not be in memory, the main advantage is that the program can be larger than the physical memory, meaning, when the RAM is not enough we use the storage device to store the memory, example : swap partition on Linux.
- To achieve this, virtual memory abstracts the main memory into a large, uniform array of storage, separating the logical memory as viewed by the user from the actual physical memory. This means the programmer or user sees a giant, continuous, unbroken line of memory addresses (logical memory), while in reality, the hardware chops the program into tiny pieces and scatters them across different parts of the RAM and the hard drive (physical memory).
- Time-Sharing systems must provide a file-system, the file system resides on a collection of disks, hence disk management is provided, it also provides mechanisms for concurrent execution, also it ensures orderly execution by priority for it this uses job synchronization, also it makes sure that jobs do not gets into deadlock and waits forever.

## Multiprocessor Systems

- Before single processor systems were common, then came multiprocessor systems (aka parallel systems or tightly coupled systems), these were able to share the computer buses, clock, and sometimes memory and peripheral devices.
- These have 3 main advantages:
	- Increased throughput, by increasing the number of processors, we have greatly increased the speed of the work done, also the processing power doesn't add with N number of processors, it's always a little less.
	- Economy of scale, they can save money, instead of buying multiple single processor systems, we can buy one multiprocessor system.
	- Increased reliability, if we have multiple processors and one fails then the other processors can work instead of halting all the processes, it just slows down the processor but it still works, this ability is called **graceful degradation**, the systems that are designed for graceful degradation is called **fault tolerant**.
- If one processor fails there should be a mechanism to allow the failure to be detected, diagnosed and if possible corrected, the Tandem (dominant manufacturer known for **fault-tolerant computer systems**) system uses both hardware and software duplication to ensure the system runs despite failure.
- This duplication ensures that the data and the processing stays as is, but it is expensive, the most common multiprocessor systems uses **symmetric multiprocessing (SMP)**, in SMP each processor runs an identical copy of the operating system, and these operating systems are able to communicate with each other, all processors are peers meaning each processors run by their own without a master processor, each processor runs a copy of the operating system.
- Some systems use **asymmetric multiprocessing**, in which each processor is assigned a specific task, this works by a Master-Slave relation, one processor is the master and the rest are slaves, the master assigns work to the slaves.
- SMP can be configured such that it employs dozens of processors, all running UNIX copy, the benefit is that it can run N times faster with N number of processors without any loss in performance, we much be careful with I/O control to make sure that data reaches the appropriate processor, also we need to make sure that every processor is sharing the work load instead of one sitting idle and the rest are being overloaded, these are inefficiencies, these can be avoided if the processors share certain data structures.
- All latest modern operating system support SMP, as it's common in this era.
- The difference between Symmetric and Asymmetric multiprocessing can be either hardware or software, the software can be written to make master-slave (one master, multiple slave) processors, also SunOS (version 4) provides Asymmetric multiprocessing, where as SunOS (Version 5) provide Symmetric multiprocessing on the same hardware.
- In fact, microprocessors are super common that it is no longer considered multiprocessing.

## Distributed Systems

- A network, in the simplest terms, is a path between two or more systems to communicate with each other, distributed systems depend on networking for them to function, by communicating through network, distributed systems, are able to provide a rich set of features.
- TCP/IP is the industry-standard network protocol suite, used universally across platforms like Windows and Unix. However, operating systems can utilize any network protocol, provided the underlying network interface possesses compatible hardware drivers and the system running appropriate software to transmit and receive data packets.
- **PAN (Personal Area Network)**: Operates within a very short range (typically up to 10 meters) for personal devices, commonly utilizing **Bluetooth** or Wi-Fi.
- **LAN (Local Area Network)**: Confined to a single physical location—such as a single room, a home, an office, or an entire building.
- **MAN (Metropolitan Area Network)**: Spans a larger geographic area than a LAN, typically covering an **entire city or town** to link multiple local corporate or public buildings.
- **WAN (Wide Area Network)**: Covers vast geographical distances, linking networks across cities, countries, or globally (the Internet is the ultimate example).
- **SAN (Storage Area Network)**: A dedicated, high-speed network that connects **servers to data storage devices** (like disk arrays or tape libraries), making them appear locally attached to the operating system.
- The media to carry the network is also varied, they include, copper wires, optic cables, fiber strands and wireless transmissions.

## Clustered Systems

- Like **parallel systems**, clustered systems gather multiple CPUs to accomplish computational work. While definitions can vary, a generally accepted definition is that clustered systems share storage and are closely linked via a Local Area Network (LAN).
- This setup is usually deployed to provide **high availability**. A layer of cluster software runs on the cluster nodes, allowing each node to monitor one or more of the other nodes over the LAN. If a monitored machine fails, the surviving node takes ownership of its storage and restarts the applications that were running on the failed machine. This automatic failover prevents users and clients from experiencing service interruptions.
- In **Asymmetric clustering**, one machine is in **hot standby mode**(backup system) while the other applications are running, the hot standby host(machine) observes for any failure, if that server fails this jumps in and takes over the processes.
- In **Symmetric clustering**, two or more machines running, this is way more efficient than asymmetric clustering, cause it uses all the hardware, instead of waiting for a machine to fail, they monitor each other, also run along.
- Other forms like **parallel clustering** and **clustering over WAN** also exists:
	- Parallel clustering is when multiple nodes simultaneously access the same storage and run instances of the same application at the same time.
	- Clustering over WAN links nodes separated by long physical distances.
- A **Distributed Lock Manager (DLM)** is the traffic controller of a parallel or active-active cluster. Its sole purpose is to **prevent data corruption by coordinating simultaneous access to shared resources** (like files or database rows) across multiple distinct cluster nodes.
- Clustered system use and features expanded greatly via Storage Area Networks (SAN).

## Real-Time Systems

- These have strict time constraints, meaning it will have to complete a process in a set amount of time, if it takes longer the process fails.
- Responses are immediate within the time constraints (time limits).
- Real-time systems have 2 flavors:
	- Hard Real-time systems, have strict deadlines where missing a target constitutes a total system failure. (Example: airplane autopilots)
	- Soft Real-time systems, allow occasional delays, resulting in degraded quality but not catastrophic system crashes. (Example: online games)

## Handheld Systems

- Any portable, battery-powered computing device small enough to be operated while held in your hands is a handheld system. These can be smartphones, handheld gaming PCs, tablets, or any device that meets these requirements.
- These devices are limited in processing power and storage capacity, as their small physical size severely restricts the space available for internal components.
- The processor power is limited due to the compact size and heat dissipation issues; furthermore, the overall power draw is strictly constrained by battery capacity.
- Because of this limitations, the handheld system's operating systems are very much well optimized to squeeze in as much of process within the limited space.
- Before long ago, virtual memory was only for PCs, but nowadays, these are becoming common, in most of the smartphones, we got virtual memory with different names like memfusion or similar.
- The virtual memory partially extends the limitations of the memory.
- And lastly, the screen, the screens of a smartphones can't be compared to a desktop, even though smartphones with foldable technology (even trifold) are being created it can never match the feel of a desktop monitor (If it's OLED then it's unbeatable in quality).

## Compute Environment

We saw the types of OSes, now, let's see how they are used in different environments:
### Traditional Computing

- We have work-from-home options these days, but way before, people had to go to companies and use a shared system to get remote access and do their work, and those remote systems were awkward (the author said this, don't blame me).
- Before the internet was everywhere, office computers were standalone workstations. They were either completely isolated or plugged into a basic Local Area Network (LAN) just to fight over who got to use the _one_ single, loud printer in the office.
- To deal with those awkward remote setups, companies tried using **thin clients**. These were basically computer monitors with a keyboard and zero brainpower of their own, relying entirely on a big server in the back room to do all the heavy lifting (kinda like our brain during exams or viva).
- In the ancient times of traditional computing, you couldn't just click a button and get results. You had to submit a "batch job" to a central mainframe computer and wait hours (sometimes days) just to find out your code had a missing semicolon.
- But due to web technologies, companies implemented portals for employees to work from home, which can be accessed from anywhere with a secure and stable connection.
- A few companies even offer VPN access to stay secure while working.

### Web-Based Computing

- Instead of installing massive, heavy software onto your machine, everything runs directly inside a web browser. If you have a working browser, you have a workspace (and a highly convenient way to scroll through 1337x).
- Because the heavy lifting happens on a remote web server. You can access your work from a cheap laptop, a tablet, or even a smartphone while lounging in your underwear.
- Since everything is handled over the internet, your files are saved automatically to the web. This completely saves you from that inevitable heart attack when your computer suddenly shows the blue screen of death or windows starts updating.

### Embedded Systems

- Unlike your PC that can run 50 chrome tabs (with 8k tentacle PORtfolio) at once, an embedded system is a tiny computer tucked inside a larger machine built to do exactly _one_ specific job. Think of things like washing machines, smart fridges, or pacemakers (where you definitely don't want a random Windows update screen popping up).
- These systems are heavily locked down. They have tiny microcontrollers with very limited memory and processing power, meaning they can't handle complex software and no, they absolutely cannot run _DOOM_.
- Many embedded systems are "real-time systems," meaning they must respond to inputs instantly. If a car's airbag system takes an extra two seconds to calculate its job because it's loading a background task (like Copilot spying on your tabs), that is a very bad day.

If your brain is completely fried, just remember these four analogies:

- Operating systems adapt to their jobs.
    - A server OS is a massive, heavy-duty cargo train.
    - Your phone's OS is a battery-saving electric scooter.
    - The OS in your washing machine (**Embedded**) who knows exactly one job and never asks you to install a software update.

**The Bottom Line:** Without an Operating System, your computer is just a very expensive, very useless brick of metal and plastic. It is the invisible boss that makes the hardware actually do what you want.
